03 / 08

Where they disagree

Five Tensions

Not everything points the same way. These are genuine trade-offs.

Process vs Speed
Toyota: standardize everything, improve incrementally. Netflix: remove all controls, trust talent. Linear: say no to process. Amazon: document everything in 6-page memos. Resolution: scale process with decision size. Bug fix = no process. New data model = full process.
Plan vs Discover
Amazon: write the PR/FAQ before building. Lean Startup: ship the MVP and learn. Gall: start simple, don't design upfront. Resolution: write a 1-page brief (intent), then experiment. Not a 6-page spec, not a blind prototype.
Autonomy vs Alignment
Netflix: full autonomy. Bridgewater: full transparency. Toyota: standardized work. Art of Action: autonomy within intent. Resolution: share intent broadly, let agents decide method. Bungay wins.
One Agent vs Many
Multi-agent research: coordination overhead is real, 2-5x more tokens. But Writer+Critic pattern reduces errors 15-30%. Resolution: one agent with structured self-review for most tasks. Multiple only for genuinely separable work.
Document vs Ship
Stripe: write everything down. Linear: ship small, fast. Gall: don't build systems you don't need. Resolution: document decisions and boundaries. Don't document implementation. The code IS the documentation for how things work.

How LLMs actually work

What This Means
for AI Agents

LLMs interpolate, not reason
They generate the most probable completion given context. Your job: make the correct output the most probable one.
Context is programming
Every token biases output. Irrelevant context actively hurts. Include only what makes the correct answer most likely.
Multi-file changes are the failure mode
LLMs lose coherence across files. One file per task. Validate after each. Types as contracts between files.
Feedback loops beat better prompts
TypeScript strict mode prevents more errors than any prompt instruction. Compile after every change. Test after every feature.
The repo map is the killer feature
A structural overview of the codebase (signatures, relationships) in every prompt. 2-3 hops of context beats dumping everything.

The operating model

What Emerges

Across all 23 sources, one model keeps appearing in different forms.

1
Sense
Ideas form from feedback, data, observation, user pain. Toyota's gemba. Amazon's customer obsession. Lean's Build-Measure-Learn.
2
Frame
Write the intent. PR/FAQ (Amazon). A3 (Toyota). Hypothesis (Lean). Not detailed plans — clear intent with boundaries.
3
Scope
Assess impact across layers and domains. Which shearing layers? Which bounded contexts? What's P1 vs P2? What to say no to?
4
Execute
Build layer by layer. One file at a time. Validate after each. Knowledge system checks boundaries. Agents work within intent.
5
Verify
Sensors run. Design QA. Type check. Tests. Did we break anything? Did we cross a boundary without checking?
6
Learn
Monitor outcomes. Analytics. User feedback. 5 Whys on failures. Update the knowledge system. Feed back into Sense.

Sense → Frame → Scope → Execute → Verify → Learn → Sense
This is the unified loop. Every source contributes to a different step.
