03 / 12

7 Universal Principles

Machine-readable. Each has a trigger condition and violation signal.

P1
Make work visible and explicit
If it is not written down, it does not exist for agents.
Violation: "I assumed..."
P2
Constrain to accelerate
Limit scope, context, and WIP. One task at a time.
Violation: Generic output
P3
Feedback loops determine health
Every action produces a measurable signal. Tighter loop = faster learning.
Violation: No way to measure
P4
Separate things that change at different rates
Consult shearing layers. Cross-layer coupling needs contracts.
Violation: UI needs data change
P5
Start simple, earn complexity
Build the simplest thing that works. Add complexity only when proven insufficient.
Violation: Abstraction before 3 uses
P6
Align by intent, not instruction
Tell agents WHAT and WHY. Leave HOW open.
Violation: 20 numbered steps
P7
Decisions need an owner
Every decision has exactly one DRI. "The team decided" is not allowed.
Violation: No owner named

The Idea Flow

SENSE
SHAPE
DECIDE
SPECIFY
EXECUTE
LEARN
FEEDBACK LOOP
SENSE Founder

Identify signals: Pull (user feedback), Push (founder vision), Pain (bugs, annoyance). Gate: signal appears 3+ times.

Artifact: Signal entry in pain/ideas log
SHAPE Founder + Agent

Turn signal into 1-page brief: customer intent, hypothesis, boundary conditions, risks, impact map.

Gate: Brief stress-tested, risks mitigated
DECIDE Founder

Apply 2x2 matrix: reversibility vs data richness. Experiment, debate, captain call, or taste.

Artifact: Decision record with P1/P2/P3 scope
SPECIFY Agent drafts, Founder confirms

Three parallel specs: Product (user experience), Technical (system changes), Verification (acceptance criteria).

Gate: Founder confirms backbrief
EXECUTE Agent builds, Founder reviews

Build layer by layer, slowest first. One file at a time. Run sensors after each change. Commit per logical unit.

Gate: All sensors pass + founder approves
LEARN Founder + Agent

Three outputs: decision update (pivot/persevere/kill), process update, knowledge archive. Insights feed back to SENSE.

Closes: Feedback loop to sensing

06 / 12

Operating Intensity

Match process weight to change size. Small changes skip stages.

S
SMALL

Quick Fix

~5 min
Files: 1-3
Commits: 1
Sessions: 1
Flow: Sense to Execute (skip Shape, Decide)
Brief: 3 sentences
Spec: 3 bullets
Known issue, obvious fix. Bug in single component. Content string change.
M
MEDIUM

Feature Gap

1-3 days
Files: 5-15
Commits: Multiple
Sessions: 3-7
Flow: Full 6-stage flow
Brief: Full 1-page
Spec: 3-part, 1-2 pages
New screen or interaction. Multi-file refactor. New design pattern.
L
LARGE

Architecture

1-3 weeks
Files: 15+
Commits: Feature branch
Sessions: 7-20
Flow: Full flow + feasibility spike
Brief: Brief + tech spike
Spec: Multi-page + diagrams
Data model change. New bounded context. Core architecture shift.
!
EMERGENCY

Incident

Minutes
WIP limit: 0 for features
Protocol: 7-step
Sessions: Until fixed
Flow: STOP → ASSESS → TRACE → FIX → VERIFY → LEARN → RESUME
Production broken. Data corruption. Silent failures (virtual ID bugs).

Decision Framework

Who decides what, and how confidence maps to action.

Decision Matrix (2x2)

High Reversibility
Low Reversibility

Founder Taste
Intuition + principles

Confidence Scoring

< 0.5
Present alternatives, founder decides
0.5-0.8
Agent recommends, founder can override
> 0.8
Low risk: proceed. High risk: still needs founder.

Agents Decide Autonomously

Single shearing layer only
Single bounded context only
Low risk, reversible (< 1 hour to undo)
Consistent with existing patterns
Examples: Fix bug in one component, refactor one file, update content strings, add test, apply existing design token

Founder Decides

Any layer boundary crossing
New design token or visual pattern
Data model or ID system change
New dependency (npm, API)
Rendering rule changes
P2/P3 scope expansion
Killing a task or commitment
09 / 12

The 6 Sensors

Run before every commit. Any failure blocks until resolved.

1

Design Token Compliance

Checks: No hardcoded hex in .tsx files
When: Any .tsx file commit
Pass: Zero hardcoded colors
Failure = component bypasses theme system
2

Theme Values Match Spec

Checks: theme.ts matches DESIGN.md
When: theme.ts or DESIGN.md change
Pass: All key values match
Failure = spec and implementation diverged
3

Virtual ID Safety

Checks: Store has no ID manipulation. Callers resolve virtual IDs.
When: Store or screen changes
Pass: Clean boundary
Most dangerous failure: silent DB no-ops
4

Rendering Rule Consistency

Checks: CanvasScreen filters match DESIGN.md rules
When: Canvas, DESIGN.md, or store changes
Pass: Code filters = spec
Failure = users see wrong visual treatment
5

Seed Data Safety

Checks: No INSERT OR REPLACE for user data
When: seed.ts changes
Pass: INSERT OR IGNORE only
Failure = hot-reload overwrites user edits
6

Type Safety

Checks: TypeScript compiles with zero errors
When: Every commit
Pass: npx tsc --noEmit = 0
Failure = type contract broken. No @ts-ignore.
10 / 12

The Learning Loop

The system improves itself. Every incident and metric feeds back into the model.

INCIDENTS

Incidents Update Sensors

Every incident produces at least one systemic improvement:

1 New sensor if none caught it
2 Updated Change Flow Map if dependency was undocumented
3 Updated boundary contract if unclear or missing
4 Decision record with root cause and prevention
Incident is not closed until a systemic improvement ships.
ANALYTICS

Analytics Feed Ideas

Input metrics to track (each with a hypothesis):

Actions per session
Are users doing things or just looking?
Quick-add usage rate
Is NL input reducing friction?
Time-to-first-action
How fast can a new user capture a thought?
Session length trends
Shorter (efficient) or longer (engaged)?
Unexpected movement in any metric triggers a new signal in the SENSE stage.
DECISIONS

Decisions Get Tracked

Outcome field filled 2-4 weeks post-decision:

Result
Did the hypothesis hold?
Surprises
What we did not anticipate
Quality rating
Good / neutral / bad
Would decide differently?
Calibrates future confidence
Quarterly: review all outcomes. High confidence + bad outcome = our models are wrong.

What Changes From Today

From scattered process docs and ad-hoc decisions to one coherent system.

BEFORE
x 12+ scattered process documents
x No clear idea-to-shipped pipeline
x Agents guess what to load into context
x Decisions made ad-hoc, not recorded
x No sensors — bugs caught manually
x Incidents fix symptoms, not systems
x Unclear when agents act vs ask founder
x Departments model — too complex for 1 person
AFTER
1 One document — the single source of truth
6 Idea Flow stages — Sense to Learn, every time
4 Context rings — agents load exactly what they need
D Decision records — every call logged with outcome
6 Sensors — automated checks before every commit
L Learning loop — incidents improve the system itself
B Bounded autonomy — clear agent vs founder decisions
3 Layers + Domains + Stream — 3D impact model
Supersedes 12 documents including CHARTER.md, PROCESSES.md, ROUTING.md, STANDUP-PROTOCOL.md, and all department files. Active docs (CLAUDE.md, DESIGN.md, PKS, etc.) remain and conform to this model.
