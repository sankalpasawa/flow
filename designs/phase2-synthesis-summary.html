Why These Principles
Hit Harder for AI

AI agents have zero persistent memory. Every principle intensifies.

P1
Visibility is a physical constraint
If it's not written down, it literally doesn't exist for the agent. No tribal knowledge.
P2
Context window IS the constraint
4k focused tokens outperforms 200k unfocused tokens. Less noise = better output.
P3
Feedback loops in seconds, not weeks
Agent writes code, runs tests, sees failures, fixes -- all in one session. Exploit this.
P6
Intent prompts beat instruction prompts
"Ensure visual consistency" outperforms "Step 1: check colors. Step 2: verify spacing."

Tension Resolution Framework

When to Apply Which

Standardize
Repetitive work, high variance cost. Data models, schemas, deploy pipelines.
Remove Controls
Creative work, high conformity cost. Strategy, design exploration, problem-solving.
Plan Thoroughly
High cost of failure, irreversible. New products, data model changes, core infra.
Experiment Rapidly
Low cost of failure, reversible. UI changes, copy, feature variations, pricing.
Meritocracy
Technical + analytical decisions. Architecture, metrics, experiment interpretation.
Founder Taste
Aesthetic + product decisions. Design, brand, UX, coherence of vision.
Toyota's Universal Insight
PDCA always applies -- the CYCLE TIME varies. PR/FAQ = 6-week cycle. A/B test = 2-week cycle. Type check = 2-second cycle.

Section 3

The Node Hierarchy

13 competing node types from 13 sources. Synthesized into three levels that map to natural cadences.

Level 1 -- Mission
Slow-changing, intent-level
"Make task management delightful for solo knowledge workers"
Changes: monthly-quarterly Owner: Founder
Maps to: Art of Action mission, Amazon PR/FAQ, Netflix context memo
Level 2 -- Commitment
Medium-changing, scope-level
"Build a natural language quick-add feature"
Changes: weekly-monthly Owner: DRI
Maps to: DRI assignment, design doc, bounded context, standard
Level 3 -- Task
Fast-changing, execution-level
"Implement parseActivity function for NL time extraction"
Changes: daily-hourly Owner: Agent
Maps to: Linear issue, feature flag, experiment, constraint
Context Loading Order
Agent loads: Mission (stable) -> Commitment (refreshed weekly) -> Task + Decisions (per session) -- slow to fast, matching Brand's shearing layers

Section 6

LLM-Compatible
Operating Model

6 design principles that make the model work for AI agents, not just humans.

1. Layered Context Loading
Ring 1 (always, ~500t): Identity. Ring 2 (per-role, ~2kt): Role. Ring 3 (per-task, ~5kt): Task. Ring 4 (on demand): Reference.
2. Structured Artifacts Over Prose
YAML-style decisions, not paragraphs. Agents parse structure; they skim prose. what/chose/why/rejected.
3. Decision Logs as First-Class
Consistency across sessions. Pattern learning from examples. Understanding WHY, not just WHAT.
4. Templates Over Rules
Concrete patterns agents can match and extend, not abstract principles they must interpret.
5. State Machines for Processes
DRAFT -> REVIEW -> REVISE -> APPROVE | KILL. Agent always knows: current state, valid next actions, transition criteria.
6. 2-3 Hops, Not the Whole Graph
Task + parent commitment + grandparent mission + siblings + dependents. Not every task across every mission.
Core constraint: No persistent memory. Everything not written down does not exist. Recency bias means most important info loaded LAST.

Section 8

The Three-Layer
Operating Model

Identity, Operating System, Execution -- three layers, three rates of change, loosely coupled.

LAYER A
Identity
Purpose, vision, principles, taste. Single IDENTITY.md document, always loaded in Ring 1 context.
Changes: Yearly
Owner: Founder
Review: Annually
LAYER B
Operating System
Processes, standards, decision frameworks, domain definitions. Loaded per-role in Ring 2.
Changes: Quarterly-Monthly
Owner: Founder + agent input
Review: Monthly
LAYER C
Execution
Missions, commitments, tasks, decisions, metrics. Structured nodes loaded per-task in Ring 3.
Changes: Daily-Hourly
Owner: DRI per node
Review: Weekly / Daily / Per-session
Agent Architecture
Phase 0: One agent, founder as DRI
Phase 1: Specialized agents per domain
Phase 2: Shared task board + decision log
Phase 3: Orchestrator agent (earned)
Cadences
Per-session: Task execution + learning
Daily: Review progress, unblock
Weekly: Review commitments
Monthly: Evaluate missions + experiments
Quarterly: Update identity layer
