Unit tests, design QA, sensors, edge cases

🔄 Negotiation round
Agents review each other's specs. Conflicts surface.
↕
Design → Tech conflict: CDO wants color-coded tag chips. CTO says "per-tag color needs a new table, not JSON array. Adds 2 days."
↕
Tech → Design feedback: CTO says "JSON array means no server-side tag search. Design around client-side filtering."
↕

Design adjusted for tech constraints. Tech adjusted for design needs. Trade-offs documented.

P2: autocomplete + colors + filter (2 weeks)
P3: hierarchy + smart groups (future)
Cross-feature: update AI schema, seed data, Play screen

👑 Review + approve
You see the mockup. Taste call on design. Approve P1 scope. Go.
Specs approved → build P1

Phase 4: After shipping

Monitor, Learn,
Handle Incidents

CDaO agent (analytics)
📊 Monitor adoption
Tag usage rate, avg tags per activity, search by tag frequency
↓
📈 Positive signal
"40% use tags. Retention 1.3x for tag users." → Validate P2. Build autocomplete.
📉 Negative signal
"80% use 0 tags. No retention lift." → Pivot. AI auto-suggest tags instead.
↓
🔁 Learn → next cycle
Data updates RICE scores. Informs next feature decision. The system gets smarter.
🚨 P0 Incident
"Users losing activity data after tag migration"

Bypasses all process. Speed first.
Detect (minutes) → Triage (15 min) → Fix (1 hour) → Deploy
Post-mortem (24 hours) → Update sensors + knowledge system
ALL HANDS — drop everything
↓
📝 Post-mortem updates the system
New sensor: "check NULL values before migration." New failure flow entry. System learns from pain.
06 / 07

How much process per change

Operating Intensity

Not every change needs the full flow. The process scales with the size of the change.

🟢 Small (bug fix, copy change)
Read knowledge system → fix → sensors → commit
5-30 min
Skip strategy. Skip specs. Just read the change flow map and fix at the right boundary.
🔵 Medium (new screen, UI rework)
Brief strategy → design mockup → build → verify
1-3 days
CPO + CDO weigh in. Design mockup for your approval. Then build. No full impact scan unless crossing Layer 1.
🟠 Large (new data model, major feature)
Full strategy → all specs → negotiate → scope → build → full QA
1-3 weeks
All agents involved. Full impact scan. P1/P2/P3 scope. Layer-by-layer build. This is the complete flow.
🔴 Emergency (P0, data loss, crash)
Fix first → process second → post-mortem updates system
Minutes
Skip everything. Fix the problem. Then do the post-mortem. The system learns after the crisis, not during.
The trigger: Does this change cross a shearing layer boundary?
No → Small. One boundary → Medium. Multiple boundaries → Large.
