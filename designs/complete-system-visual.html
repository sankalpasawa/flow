Layer 1: Strategy

What gets produced

The org agents work here. Multiple agents run in parallel. Founder approves.

1
Product Requirement Document (PRD)
CPO Agent → Parallel
📄 Problem statement, user stories, success metrics
📊 RICE score (Reach × Impact × Confidence / Effort)
⚠️ Edge cases: empty state, 0 items, 100 items, error, offline
→ org/features/{slug}/PRD.md
2
Cross-Functional Impact Assessment
ALL Agents → Parallel
🔒 Security: input validation, privacy, compliance
📊 Analytics: events to track, dashboards, A/B test plan
🚀 Growth: retention impact estimate, onboarding changes
✅ Quality: test cases needed, regression risks
→ org/features/{slug}/IMPACT.md
3
Roadmap + Priority Scope
CPO + CEO (Founder)
🏷️ P1: must ship (core functionality)
🏷️ P2: should ship (polish, edge cases)
🏷️ P3: nice to have (advanced, can defer)
📋 Tasks that touch OTHER features (update list)
→ org/features/{slug}/ROADMAP.md
FOUNDER APPROVES → proceed to specs

Layer 2: Specification

Three specs in parallel

Three agents run simultaneously. Each produces a spec document + artifacts.

A
Design Spec
CDO Agent
🎨 Visual design: layout, spacing, colors, glass treatment
👆 Interactions: tap, swipe, long-press, animations (spring values)
📐 All states: default, loading, empty, error, compact, completed
🖼️ HTML mockup in designs/ folder
♿ Accessibility: touch targets, labels, contrast
→ org/features/{slug}/DESIGN-SPEC.md + designs/{slug}.html
B
Tech Spec (HLD + LLD)
CTO Agent
🏗️ HLD: which shearing layers touched, architecture impact
📁 LLD: exact files to create/modify, DB migration SQL
🔗 Change Flow Map entries (from Knowledge System)
⚠️ Risks: what could go wrong, virtual ID implications
📦 Build order: which layer first, commits per layer
→ org/features/{slug}/TECH-SPEC.md
C
Test Plan
CQO Agent
🧪 Unit tests: pure function test cases with inputs/outputs
🎨 Design QA: pixel checks, token compliance
🔄 Integration: end-to-end user flow verification
📊 New sensors needed for this feature
→ org/features/{slug}/TEST-PLAN.md

Layer 3: Execution

Build, verify, ship

One agent builds. Other agents verify. Sequential within a layer, parallel across checks.

1
Build (bottom-up, one layer at a time)
Main Agent (you + me)
📝 Read specs from Layer 2 before writing code
🔽 Layer 1 first (data model) → commit
🔽 Layer 2 (business logic) → commit
🔽 Layer 4 (design tokens if new) → commit
🔽 Layer 3+5 (features + components) → commit
2
Verify (parallel agents)
CQO + CDO + Sensors
✅ CQO: run test cases from TEST-PLAN.md
🎨 CDO: screenshot + pixel compare against DESIGN-SPEC
🔍 Sensors: design tokens, virtual IDs, rendering rules, boundaries
🔒 CISO: input validation, sanitization check
3
Ship + Update
Main Agent
🚀 Commit, push, deploy edge functions if needed
📊 CDaO: verify analytics events are firing
🗺️ Update PRODUCT-KNOWLEDGE-SYSTEM.md with new entries
📋 Update TODO.md, mark feature complete

Who does the work

Agents + You

Some work runs in parallel agents. Some is sequential. You make the taste and priority calls.

👑
You (Founder)
Approves PRD. Sets P1/P2/P3. Makes taste decisions on design. Final call on trade-offs.
Human judgment
🤖
Main Agent (me)
Orchestrates the flow. Writes code. Reads knowledge system. Launches specialist agents.
Sequential — drives the process
📦🎨⚡
Spec Agents
CPO, CDO, CTO run in parallel to produce PRD, design spec, tech spec simultaneously.
Parallel — independent outputs
✅🔒📊
Verification Agents
CQO, CISO, CDaO run in parallel after code is written to verify quality, security, analytics.
Parallel — independent checks
Operating Intensity
Small change (bug fix, copy change): Skip Strategy layer. Read knowledge system. Fix. Run sensors. Commit.
Medium change (new screen, UI rework): Brief Strategy (CPO + CDO). Full Spec. Full Execution.
Large change (new data model, new feature): Full Strategy with all agents. Full Spec. Layer-by-layer Execution. Full QA.

When we have analytics

Impact estimation
feeds back in

Once we have PostHog data, impact estimates become data-driven instead of guesses.

Before analytics (now)
RICE score uses gut feeling.
"I think tags will help retention" → Confidence: 4/10
No way to verify after shipping.
After analytics (future)
CDaO agent reads PostHog data:
"Users who use 3+ categories have 2x retention"
→ Tags (more flexible categorization) → Confidence: 8/10
After shipping: "Tag users have 1.5x retention" → validated
Where this lives
Strategy Layer — IMPACT.md gets a "Data Evidence" section
CDaO agent — reads analytics, produces impact estimates
CPO agent — uses estimates to recalculate RICE scores
Feedback loop — shipped feature → monitor → learn → inform next feature

Everything on one page

The Complete Flow

STRATEGY
  You: "I want tags" → CPO, CDO, CTO, CISO, CDaO, CGO, CQO agents run parallel
  → PRD.md + IMPACT.md + ROADMAP.md (P1/P2/P3)
  → You approve. Go/no-go.

SPECIFICATION
  Three agents in parallel:
    CDO → DESIGN-SPEC.md + mockup HTML
    CTO → TECH-SPEC.md (HLD + LLD + build order)
    CQO → TEST-PLAN.md (unit + design QA + sensors)
  → You review designs. Taste calls.

EXECUTION
  Me: read specs → read knowledge system → build layer by layer
    Layer 1 (data) → commit → Layer 2 (logic) → commit → ...
  Verification agents (parallel): QA, design check, sensors, security
  → Ship → CDaO monitors analytics
  → Update knowledge system with new entries

FEEDBACK
  Analytics → "Did tags improve retention?"
  → Feeds back into RICE scores for next feature
  → Incidents update failure flow map
  → System gets smarter with every cycle
